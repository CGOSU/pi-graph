# 开发踩坑记录

本文件按日期倒序记录容易复发且不直观的问题；新增条目插入对应日期位置，最新条目在前。一次性报错、普通开发流水和未经验证的猜测不写入此处。

## 记录格式

每条记录包含：

- 日期：发现或最后验证日期；
- 现象：可观察到的错误或异常行为；
- 根因：经过确认的直接原因；
- 修复：已验证有效的处理方法；
- 验证：复现、测试或检查命令及结果。

## 已知问题

### 2026-11-04 — Tree-sitter WASM 包的 grammar wrapper 可能提高 Node 最低版本

- 现象：只想依赖 Dart/Kotlin `.wasm` grammar，安装对应 npm wrapper 却违反项目现有 Node 引擎要求。
- 根因：grammar WASM 资源包自身的 `engines` 可能要求 Node >=26，而本项目仍支持 Node >=22.19；grammar 资产和包装器的 Node 运行时要求是不同边界。
- 修复：核对上游版本及 MIT 许可证，把固定来源的 WASM 资产和许可证 vendoring 到 `grammars/`，记录 revision/SHA-256，并在加载时校验；不要为单一 grammar 无意升级 Node 最低版本。
- 验证：`tests/production.test.ts` 核对 tarball 包含资产/manifest/许可证，执行安装后解析，并验证缺失或损坏资产会失败；`npm test` 80/80。具体来源见 [设计决策](decisions.md)。

### 2026-11-04 — 排除规则必须同时约束扫描与监听

- 现象：运行日志和构建缓存不在索引中，却反复触发全量读取；多次 debounce 到期仍能堆积串行刷新。
- 根因：watcher 独立维护更短的目录正则，且只取消 timer，没有合并已排队刷新。
- 修复：复用扫描路径/ignore 规则，单独跟踪待执行刷新；监听健康也要在复用前校验文件身份，不能把“尚未收到事件”当作源码未变。
- 验证：`tests/watching.test.ts` 覆盖噪声、嵌套忽略、未知事件、刷新合并、无事件立即查询与失效兜底；实际运行结果见 [会话记录](session-log.md)。

### 2026-11-04 — 空内存 warnings 不代表持久化索引完整

- 现象：重开未变的索引后 warnings 消失；仅被跳过的超大文件变化时 revision 不更新。
- 根因：诊断只在内存构建分支赋值，被跳过文件也不在 files hash 表里。
- 修复：公开诊断及扫描诊断均随 revision 同事务保存，缺失旧元数据时重建。
- 验证：`tests/persistence.test.ts` 覆盖重开、纯警告增减、旧索引及失败事务回滚；结果见 [会话记录](session-log.md)。
